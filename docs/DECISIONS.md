# Design Decisions — Iteration 1

Feeds report §5.4 "Architecture Decisions and Rationale" and §6.7 "Algorithms and Technical Decisions".
Values marked (tunable) will be revisited after the first evaluation run.

| # | Decision | Our choice | Why |
|---|---|---|---|
| 1 | Source of code | Trimming core works only on chunks. Iteration 1 source = repo on disk; Iteration 2 adds chunks extracted from the agent's request. | Supports both local (individual) and hosted (team) gateway modes without rewriting the trimmer. |
| 2 | Chunk granularity and IDs | 4 kinds: module-level, class, function, method. A class chunk holds only the class header + class-level attributes; methods are separate chunks. Nested functions stay inside their parent. ID = `path::QualifiedName`; a repeated name in the same file gets `#2`, `#3`. | Prevents double-counting method tokens; IDs stay unique (e.g. property getter/setter share a name). |
| 3 | Tokenizer | tiktoken `o200k_base` as a proxy for all providers. | Tiers are relative (#4), so cross-provider count differences largely cancel out. Stated as a limitation. |
| 4 | Tier budgets (tunable) | Each tier is a fraction of the "full" context: aggressive 15%, moderate 35%, conservative 60%, full 100%. Aggressive has a 1,000-token floor. "Full" = what the agent sent (gateway) or top-ranked files up to 32k tokens (evaluation). | A whole repo exceeds any context window; the original SWE-bench paper likewise retrieved files up to fixed context limits. |
| 5 | Dropped chunks | In aggressive and moderate tiers, a dropped chunk directly connected to a kept chunk stays as a skeleton (signature + docstring); all others are removed. Skeleton tokens count toward the budget. | The model still knows which functions exist and their arguments. Close to HCP (AAAI 2025), which keeps declarations and prunes function bodies; we keep skeletons only for chunks connected to kept code. |
| 6 | Language scope | Python only; parser behind a `LanguageParser` interface. | SWE-bench is Python; other languages can be added without touching graph/trimming. |
| 7 | Call resolution | Rules in order: (1) imported names, (2) `self.method()` within the same class, (3) bare names within the same file, (4) a unique repo-wide name match with `resolved=False`; otherwise no edge. No edges to built-ins. | Simple and fast. Type-aware tools (jedi/pyright) only if recall turns out poor. |
| 8 | Determinism | Ties broken by chunk ID; output sorted by file path then line; never iterate a Python `set` when producing output. | Python's set order changes between runs; this would cause random test failures. |
| 9 | Versions | Python 3.11; exact versions pinned in `requirements.txt`. | Identical behaviour on all three laptops (Windows + Linux) and in CI. |
| 10 | Evaluation subset (tunable) | ~40 SWE-bench Lite tasks from `requests`, `flask`, `pytest`, `django`. Metrics: token reduction per tier, gold-file recall, gold-chunk recall (patch line numbers matched to chunk line ranges), runtime. | Mix of small, medium and large repos; gold-chunk recall is stronger evidence than file recall alone. |
| 11 | Query | Evaluation: issue text. Gateway: latest user message + recent tool outputs. Always a single `query: str`. | Same scorer interface in both settings. |
| 12 | Files skipped | `.gitignore` matches, non-Python files, files over 1 MB, `migrations/`, `vendor/`. `tests/` folders are kept. | Tests are sometimes needed to understand or fix the bug. |

## Change log
Record any later change here (report §5.5 "Design Evolution").

| Date | Decision # | Change | Reason |
|---|---|---|---|
| 2026-10-07 | 4 | A tier's budget is never below the previous tier's budget (`budget = min(max(fraction × full, previous budget), full)`). | On small repos the 1,000-token aggressive floor exceeded 35 % of full, which gave moderate a *smaller* budget than aggressive. |
| 2026-10-07 | 5 | Each tier starts from the previous tier's content. Moderate keeps aggressive's skeletons (upgrading them to full code when they fit). Conservative drops skeletons, but if that would make it smaller than moderate it brings moderate's skeletons back. Empty chunks (e.g. empty `__init__.py`) are never packed on their own. | Guarantees nested kept sets and non-decreasing token counts in every case; empty chunks only add a file header. |
| 2026-10-07 | 5 | After rendering, if the real token count exceeds the budget, the lowest-ranked chunk *added in this tier* is removed (a method's class is never removed while the method stays). | The previous tier's text fit a smaller budget, so this loop always ends within budget without breaking nesting. |
| 2026-10-07 | 7 | Extra resolution rules: `super().foo()` and `self.foo()` look one level into resolved base classes; `SomeClass.foo()` resolves to the method when `SomeClass` is imported or defined in the file; `pkg.mod.foo()` follows imported module aliases. Inheritance by rule 4 only matches classes. | Cheap, still no type inference; improves recall on class-heavy code (django, pytest). |
| 2026-10-07 | 9 | Added `httpx2` (pinned) — `fastapi.testclient` needs it; plain `httpx` is deprecated by Starlette 1.x. | API tests. |
| 2026-10-07 | 10 | SWE-bench Lite is read from the Hugging Face datasets-server JSON API with the standard library (cached in `cache/`), instead of adding the `datasets` package. Gold files = modified, pre-existing **`.py`** files only. Subset = all requests + flask tasks, then alternating pytest / django up to 40 (`eval/tasks_iter1.json`). | No heavy new dependency; non-Python gold files can never be chunked, so they would unfairly lower recall. |
| 2026-10-08 | 4 | Evaluation pool ranks files by the mean of their **top 3** chunk scores, blended 75/25 with a **whole-file BM25** score (`FILE_TOP_K`, `FILE_TEXT_WEIGHT` in `packing.py`), instead of the single best chunk. Still whole files only. | Gold file in the 32k pool: 0.625 → 0.750 on the 40 eval tasks, and 0.433 → 0.533 on 30 held-out django tasks not used for tuning. A stricter "code-looking words only" symbol rule and partial files were also tested and did not help. |
| 2026-10-08 | 1, 11 | **Gateway, shadow mode first.** Three provider formats from the start (Anthropic Messages, OpenAI Chat Completions, Gemini generateContent), each converted to one shared `Segment` list (new in `contracts.py`), so trimming and routing are written once. Shadow mode forwards bytes unchanged and only measures. Agents choose the provider by URL prefix (`/anthropic`, `/openai`, `/gemini`). | Measure real agent traffic safely before changing anything; adding a provider = one adapter. |
| 2026-10-08 | — | Gateway logs **numbers only** (tokens per segment kind, billed usage incl. cache reads/writes); never prompt text, headers or API keys. Full bodies only with `TOKENCUT_CAPTURE=1`, local, gitignored. Binds to 127.0.0.1 by default. | Prompts contain private code; billed cache numbers are needed for the cost model. |
| 2026-10-08 | 9 | `httpx2` becomes a runtime dependency (gateway's async client to providers), not only for tests. | Same pinned version; Starlette 1.x recommends it. |
| 2026-10-08 | 5, 11 | **Cache-safe trimming (phase 3).** Live Claude Code traffic showed 96 % of input tokens are cache reads (billed ~0.1×) and a cache rewrite costs ~1.25×. So: only tool results ≥ 2,000 tokens are trimmed, and a result's trim depends only on itself and earlier conversation (user request + the tool call), never on later turns. It is therefore identical every turn and the cached prefix never changes. The query is the last user message before the result, not the latest one. | Retroactively trimming history would break the cache and can cost more than it saves. |
| 2026-10-08 | 5 | Code inside tool results is trimmed to original lines (with the tool's line numbers) plus `[TokenCut: lines a-b of f.py omitted …]` markers, instead of rendered skeletons. Files the user named, or the agent already edited, are never trimmed. Gaps under 60 tokens are kept. | Edit tools need exact text; markers tell the model what to re-read. |
| 2026-10-08 | 5 | Command / search output: keep the last 40 lines, error-looking lines ± 2, then the first 15, within `fraction(tier) × size` (min 500 tokens). | Test summaries and failures are at the end or match error patterns. |
| 2026-10-09 | 10 | **Benchmark vs baselines** (`eval/benchmark.py`): TokenCut vs BM25 chunks, dense embeddings (bge-small, fastembed), head truncation, random, SWE-bench file BM25 — equal token budgets, same renderer, two settings (pure trimming of a shared neutral 32k context; whole-repo selection), bootstrap CIs and paired sign tests. Tasks: 40 dev (tuning) + 81 held-out test (`eval/tasks_iter2.json`), never tuned on. | Fair, reproducible evidence for the claim that TokenCut trims best. |
| 2026-10-09 | 5 | Aggressive tier keeps each chunk **without its callees** (`CLOSURE_HOPS`); moderate / conservative still add 1 hop. Dev: whole-repo 15% recall 0.563 → 0.621. Rejected on dev: other ALPHA values (0.5 already best), a single-chunk reserve in the pool, down-weighting common names. | Tight budgets are better spent on more relevant chunks. |
| 2026-10-09 | 5 | Optional **TokenCut hybrid**: aggressive uses TokenCut's ranking; moderate / conservative use a blend where half of the text signal is embedding similarity (`TierPacker(tier_scores=…)`). Dev: best of all methods on whole-repo selection at every budget. Embeddings cost ~13 chunks/s on a laptop CPU, so the hybrid is for evaluation / fast machines; the core gateway stays model-free. | Structure wins at tight budgets, semantics helps at larger ones. |
